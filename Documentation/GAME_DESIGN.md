# GAME DESIGN — Основы игрового дизайна

## 1. Формат игры

**КАНОН**
- Жанр: 2D Metroidvania.
- Визуальный стиль: Pixel Art.
- Мир: мрачное средневековое фэнтези.
- Основной акцент: исследование, отзывчивое перемещение, ближний бой и повествование через окружение.

Вдохновения: Hollow Knight, Lies of P, Berserk и Little Nightmares. Игра должна сохранять собственную идентичность и не копировать узнаваемые элементы этих произведений.

## 2. Основной игровой цикл

Предварительная структура:
1. Исследовать область.
2. Находить маршруты, препятствия и следы прошлого.
3. Встречать опасности и противников.
4. Осваивать пространство через перемещение и бой.
5. Находить персонажей, предметы и сюжетные фрагменты.
6. Открывать новые пути и возвращаться в ранее посещённые области.

## 3. Управление — текущее

| Действие | Управление |
|---|---|
| Движение влево | A / ← |
| Движение вправо | D / → |
| Бег | Shift |
| Прыжок | Space |
| Атака | Левая кнопка мыши |
| Вторая атака в комбо | Повторное нажатие левой кнопки мыши |
| Dash | Правая кнопка мыши |

## 4. Реализованные механики игрока

**ТЕХНИЧЕСКИЙ ФАКТ — по последнему известному состоянию скриптов**

- Горизонтальное перемещение.
- Ходьба и бег.
- Прыжок.
- Jump Buffer.
- Coyote Time.
- Variable Jump Height / Jump Cut.
- Dash с направлением по вводу или текущей стороне персонажа.
- Первая и вторая атаки.
- Комбо из двух атак.
- Блокировка разворота во время атаки.
- Хитбокс атаки, который меняет сторону вместе с персонажем.
- Регистрация попадания по EnemyHealth один раз за один взмах.

Не считать механику окончательно отполированной только потому, что она реализована. Игровое ощущение, баланс и крайние случаи проверяются в Unity.

## 5. Принципы управления

- Управление должно быть предсказуемым и отзывчивым.
- Игрок должен понимать, почему действие сработало или не сработало.
- Во время атаки направление персонажа фиксируется, чтобы анимация и хитбокс не расходились.
- Dash не должен проходить сквозь стены.
- Атака во время Dash прерывает Dash.
- Dash во время атаки недоступен.
- Не добавлять новые механики только ради количества. Каждая должна решать конкретную игровую задачу.

## 6. Боевая система

Текущая основа — ближний бой мечом и последовательность из двух атак.

Важные принципы:
- визуально читаемая атака;
- согласованность анимации и хитбокса;
- отсутствие повторного урона одной цели за один взмах;
- понятные окна нанесения урона;
- фиксация направления атаки.

Будущие системы (парирование, лечение, выносливость, дерево навыков и т. п.) не считаются утверждёнными, пока не будут отдельно спроектированы.

## 7. Первый враг как обучающий бой

Поминальный страж должен иметь медленные, хорошо читаемые атаки с подготовкой. Игрок учится наблюдать, выбирать дистанцию и уклоняться.

Сложность первого столкновения должна исходить из понимания поведения противника, а не из неожиданного урона.

## 8. Принципы разработки

Проект разрабатывается одним человеком. Поэтому:
- делать небольшие законченные этапы;
- проверять изменения в Unity после каждого этапа;
- не добавлять системы, требующие неготовых ассетов;
- переиспользовать существующие решения, если они подходят;
- отделять временные прототипы от готовых систем;
- поддерживать документацию в соответствии с реальным состоянием проекта.

## 9. Техническая среда

**ТЕХНИЧЕСКИЙ ФАКТ — по известным данным**
- Unity 2022.3 LTS.
- C#.
- 2D Physics.
- Animator Controller для анимаций персонажа.

Точные настройки объектов, компонентов и Animator необходимо сверять с актуальными сценами и инспектором Unity. Документация не заменяет такую проверку.
